## 2026-10-18 - Fix IP Spoofing and Rate Limit Bypass in Middlewares
**Vulnerability:** The rate limiting middleware and the /api/contact logging were blindly parsing `req.headers['x-forwarded-for']` to extract client IP addresses instead of using `req.ip`. This is insecure because the X-Forwarded-For header can be arbitrarily manipulated by clients if the application does not explicitly define its trust boundaries using Express's `trust proxy`.
**Learning:** Hardcoding trust in the first comma-separated value of `X-Forwarded-For` allows attackers to trivially bypass IP-based rate limiting (like contact form limits or speed test limits) and spoof their origin in logs by sending requests with forged headers (e.g., `X-Forwarded-For: 12.34.56.78`).
**Prevention:** Always use `req.ip` and let the framework (Express) securely handle proxy trust via the `trust proxy` setting. If explicit fallback is needed, fallback to `req.socket.remoteAddress` directly rather than trusting client-provided `X-Forwarded-For` strings.
