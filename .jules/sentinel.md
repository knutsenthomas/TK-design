## 2024-05-30 - [CRITICAL] Prevent SSRF using Strict Domain Validation
**Vulnerability:** The `/api/proxy-pdf` endpoint in `legacy_html/server.js` was using `.includes()` to validate the requested domain (e.g. `parsed.hostname.includes('googleapis.com')`). This is a critical security risk as it allows an attacker to bypass the validation by using a domain like `malicious-googleapis.com`.
**Learning:** URL domain validation must use strict matching (e.g., `===`) or precise trailing matches (e.g., `.endsWith('.googleapis.com')`) rather than substring matching (`.includes()`), which is easily bypassed and can lead to Server-Side Request Forgery (SSRF). Additionally, it's crucial to explicitly check for secure protocols (`https:`).
**Prevention:** Always validate protocols (e.g. `parsed.protocol === 'https:'`) and use exact matching or strict suffix matching (`.endsWith()`) for hostnames when implementing proxy endpoints or any functionality that fetches resources based on user-provided URLs.
